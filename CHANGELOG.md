# Changelog

All notable changes to this repository are documented here. The format is
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); the software
follows [Semantic Versioning](https://semver.org/). The paper version (FTC
v1.x), the specification versions this software consumes (`flow.spec/v0.x`
from polydiagram, `dec_version` from agent-dec) and the formats this

that change them — see the README's "Versioning" section.

### 2026-10-15 — control-plane mechanics (revision of 2026-10-11 within FTC v1.1; software stays 0.1.0)

The engine rules the paper and `spec/coverage-engine.md` added on 2026-10-11
(tagged **[D11]**, **[H4]**, **[D15]**, **[D13]**, **[D14]**, **[H1]**,
**[H2]**, **[H3]** there), one commit per unit, each green on its own. Every
new report key, config key and CLI flag is optional; a report produced before

gate` with the 0.1.0 inputs still runs. The companions are consumed at their
revision of the same date: `azimuth-ink/polydiagram@e768f1c` (R12–R15, DG13)
and `azimuth-ink/agent-dec@89fdc36` (authorization and completion evidence,

- **D11 — degradation semantics and the two SLIs (spec §6.7, §7.4).** The per-run reading admits declared `on_fail` edges (and the `{to | outcome}` forms of `bound.on_exceed` / `attempts.on_exceed`) as part of the plan: `via: on_fail` from a manifest, or recorded by the engine from spans where the target is not also a `next` target (a shared target, the canon's `s5 → s6`, is noted and read as primary — the manifest is the exact source); a run ending at a step with an `on_fail {outcome}` edge is read from spans as having taken it with `outcome: unknown`. Divergent: `latched-reentry`, `undeclared-outcome`, `undeclared-edge` (finding codes gated like `non-convergent-runs`); `termination: cancelled | expired` leaves unrun steps not absent. `degradation_rate` and `veto_rate` per flow with bands from `flowtrace.yaml` `slis.*` (per-flow `flows.<id>.band`), `source: manifest | spans | mixed`, `approximate`, finding `sli-out-of-band` in both directions (warn; fail with `gate: true`); an `alerts.yaml` entry with `slo: degradation_rate | veto_rate` and `bound: max | min` makes a band bound a detectability target. Report: `slis`, per-run `via` / `outcome` / `termination` / `degraded` / `vetoed` / `approximate` / `notes`, summary `degraded_runs` / `vetoed_runs` / `manifest_runs` / `unchecked`. The local reading is agent-dec's `conformance_reading` ported for parity (asserted by the tests).
- **H4 — attempts (spec §7.5).** Consecutive entries of an effect step sharing an idempotency key commitment (read from the step certificates a manifest names), or repeated boundary spans of an effect step, collapse into the declared step (`s6×2`) and count against `attempts.max`: beyond it the step's `on_exceed` is read as taken, else `attempts-over-bound`. Binding B17 is taken from agent-dec's verifier called as a library on the run's directory (`flowtrace.evidence`, the `FINDING` / `NOTE` / `FAILED` / `UNCHECKED` line contract): `retry-without-reconciliation` makes the run divergent; from spans alone it is listed under `conformance.summary.unchecked`. Report: `conformance.attempts` per effect step, per-run `findings`, input `methods`; new flag `--methods` (default: `methods/` in or beside a `--dec-dir`).
- **D15 — assurance stream, attribute classes, authorization coverage (spec §2.4, §4.1, §6.6).** Every required attribute resolves to a class — declared; else the canonical namespace table (`flowtrace.adapters.base.CANONICAL_ATTRIBUTES`, with the three effect-step digests `dec.authz_cert_digest`, `dec.completion_cert_digest`, `dec.approval_digest`) and `attribute_classes.namespace_defaults`; else `identifier`, reported `class_assumed` with the warn finding `attribute-class-assumed` (DECISION-R: never on a flow that declares the floor, where R15 requires the class). `content` attributes and the scenarios that need them (a binding's `stream`, else the `required_data` heuristic) read the sampled stream, joined by trace id (absent there = not evaluated); a content attribute on a distinct assurance export is `content-on-assurance-stream`. Floors: with `assurance_sampling_floor` the tier's floor is satisfied by the assurance stream (`assurance-sampling-below-floor`) and the sampled stream is held to the descriptor's own (`sampling-below-floor`); `assurance-floor-below-sampling-floor` for an unvalidated descriptor; `effective_sampling` is the assurance stream's. New flags `--assurance-telemetry` (must overlap `--telemetry`'s window; load error otherwise) and `--assurance-sampling-rate`; config `telemetry.assumed_assurance_sampling_rate`, `attribute_classes.*`, `scoring.execution_evidence.count_completion`. Execution evidence gains the effect-step population: `dec.authz_cert_digest` verifies when it names a `kind: authorization` record that verifies in `policy_authorities[]`, binds to the span's flow / step / run, is an `allow`, and carries no step-1d finding (statuses `verified | artifact-not-found | signature-invalid | authority-not-trusted | flow-mismatch | run-binding-mismatch | denied | authorization-expired | authorization-stale | approval-invalid | unverifiable`); pooled into the score and reported apart (`certificate_coverage`, `authorization_coverage`); `completion_status` and `approval_present` resolved and reported; `count_completion` pools a third population. Report: `streams`, per-attribute `{class, class_assumed, class_source, stream}`, scenario `stream`, inputs `assurance_telemetry`; warn finding `authorization-missing`.
- **D13 — hosted set-bounded methods (spec §6.5).** A `configuration_record` certificate (`method.kind: hosted`, `replay: none`) is in the ND0/ND1 population and verifies on the same conditions — the engine never replays; `evidence_types` tallied per verified instance.
- **D14 — gate authority (spec §6.7).** Binding B12 is the companion validator's R14; the engine does not re-check it. The reading carries agent-dec's gate-authority note (a `block` reached from a step not declared ND0/ND1) as a divergence reason; never on the 2.1.0 example.
- **H5 — claims manifests.** No flowtrace work (agent-dec's step 1c; FTC states nothing that depends on it).
- **H1 — effect steps without authorization (spec §7.6).** `effect-without-authorization` from agent-dec's step 1d (`reason_class: missing | denied`) makes the run divergent and is a gated finding code; from spans alone B10 is unchecked. `authorization-expired` and `authorization-stale` (B16, against the flow's `max_decision_age_s` through the verifier's `--flow-registry`) are passed through as warn findings and are statuses of authorization coverage; never re-derived.
- **H2 — human approval.** `dec.approval_digest` resolves to the `human_approval` attestation from `approvals/` beside each run's chain or `--approvals` (verifies in `approvers[]`, binds to the span; `approval_present.resolved`); `sod-violation` and `approval-payload-mismatch` passed through as warn findings and read as the status `approval-invalid`. New flag `--approvals`, input `approvals`.
- **H3 — cancellation across runs (spec §7.7).** For a cancelled parent with `children[]`, every child's run certificate (by `subject.run_id` in `--dec-dir`, then `--runs-dir`; it must verify) must record `termination: cancelled | completed` with `issued_at` within `cancel_propagation_s` (the flow's, else `conformance.cancel_propagation_s`) of the parent's `terminated_at` (else its run certificate's `issued_at`); otherwise `cancellation-not-propagated` with `reason_class: not-terminated | late | certificate-not-found` (expired and failed children are not-terminated — the literal B14; a child not found without `--runs-dir` is unchecked). New flag `--runs-dir`; report `conformance.cross_run`, per-run `children[]`.
- **Running example 2.1.0.** `examples/flows/quote-issue.flow.yaml` is canon §7.1 (sha256 `bcbf4315…`); `examples/dec/` is agent-dec `89fdc36`'s signed set verbatim (`SOURCE`): the dec-trust/0.2 bundle, methods, the flow-bound run with its s6 evidence, the variants, the cancelled pair, the negatives, the hosted run. ### Decisions recorded (2026-10-15)
- Bands live in `flowtrace.yaml` (`flow.spec/v0.2` carries no band field); a descriptor band, if a later schema carries one, would win (spec §6.7).
- Degradation edges, for the reading and the SLIs, are `on_fail` and the `{to | outcome}` forms of `bound.on_exceed` / `attempts.on_exceed` (binding B9 as agent-dec reads it); polydiagram's DG13 counts `on_fail` edges only — recorded as a spec note, not narrowed here.
- Authorization coverage pools with certificate coverage under the execution-evidence weight and is also reported separately; completion evidence is reported, not scored, unless `count_completion` is set.
- The step-1d readings (B10, B11, B15, B16, B17) are taken from agent-dec's verifier called as a library on each run directory and parsed from its documented line contract; the engine never re-implements chain, signature or evidence-order checks. B14 (timing and termination of child runs) is the engine's own cross-run reading; a child's run certificate is verified before its termination counts.
- The sampled-stream heuristic for scenarios (`required_data` naming a `content` attribute) is a fallback; a binding's `stream` is the contract.
- `scoring.execution_evidence.run_binding: warn` stays the default for the same reason as in 0.1.0: each window reuses one signed run's digests across 32 synthetic runs, so B7 (and now B7 extended to authorization records) is satisfied while run binding is reported for 31 of them.

### Decisions recorded
- Execution evidence is off by default (`scoring.execution_evidence.enabled: false`; the paper calls the component optional) and on with `--execution-evidence`; when on, `--trust-bundle` and `--dec-dir` are required.
- `scoring.execution_evidence.run_binding: warn` by default: B7 (trust-bundle verification + `subject.flow` match) decides the score; a certificate that does not bind to the span's run (`subject.run_id != trace id`) is reported, and `strict` makes it fail. The shipped example reuses the one signed run across synthetic runs, so `strict` would score 1/32 there.
- A not-evaluated scenario (placeholder with no binding, or a dialect the adapter does not execute) scores zero, like an unanswerable one, so a P0 flow cannot pass with unevaluable scenarios.
- Components that are not applicable to a flow are dropped and the remaining weights renormalized; a component the tier requires (answerability for P0) is always applicable.
- Segment (edge) terms are not modeled separately in 0.1.0: each hop's latency is counted inside the receiving step (one of the two treatments FTC §4.3 discloses).
